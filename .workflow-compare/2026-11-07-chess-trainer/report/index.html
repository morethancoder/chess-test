Same chess app. Built five ways.

Five workflows got the same brief: a one-page chess trainer with pass and play, 12 mate puzzles and the full rules, tested. Each build ran on its own, with no human answering questions. Every build runs twice, then an Opus reviewer grades all ten without knowing which workflow made which.

What the run turned up

A wrong price in Claude's own API notes

The bundled claude-api skill lists Sonnet 5.5 cache reads at $0.20 per million tokens. The live pricing page says $0.10. The test harness checks its prices against the CLI's own cost figure, which caught the gap: every Sonnet session was overpriced by 16 to 32%. Fixed, and every price now matches.

Tight command rules, same for everyone

Each build had 2 to 11 shell commands refused: chained commands, PORT=… npm prefixes, writes to /tmp, and tools like head and sed. When reading $PORT was refused, the Sonnet builds made up port 5199. D was hit least, because its helpers ran the shell work. Kept the same in round 2 so the rounds compare.

Every build plays real chess

All five count moves exactly right from the start position and from Kiwipete, the standard stress position for castling, en passant and pins. All pass their own tests, the end-to-end tests and the production build, with no console errors and no sideways scroll on a phone.
